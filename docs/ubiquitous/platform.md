# オントロジープラットフォームのユビキタス言語

この文書は、オントロジープラットフォームを利用してモデルを定義し、データを登録・検索する際に使う言葉と意味を揃えるためのものです。用語は利用者から見える概念で定義し、データベース、通信方式、生成コードなどの実装では定義しません。

## モデルを表す言葉

### オントロジー

対象世界にどのような種類のものがあり、それらがどのような情報と関係を持つかを表したモデルです。Entity 型、Property、Link 型の定義をまとめたものを指します。

### オントロジー定義

オントロジーの内容を、プラットフォームが解釈できる形で記述したものです。実際の Entity や Link の集まりであるデータとは区別します。

### Entity 型

同じ種類の Entity が持つ意味と Property を定めたものです。たとえば、ある対象を一つの種類として識別し、その種類に属する Entity が持てる Property を定義します。

「Entity の型」「種類」も同じ意味で使わず、文書と会話では **Entity 型**に統一します。

### Entity

対象世界に存在する、個別に識別したい一つのものです。Entity は一つの Entity 型に属し、同じ型の別の Entity と区別できる ID を持ちます。

Entity は保存先の行や API の payload ではなく、利用者が識別して情報を持たせたい対象そのものを意味します。

### Property

Entity が持つ一つの情報です。Property は Entity 型の中で定義され、名前、意味、Property 型、必須性を持ちます。実際の Entity では、定義された Property に値または null を持たせます。

「属性」「field」「column」ではなく、モデル上の概念を指す場合は **Property**を使います。

### Property 型

Property が取り得る値と、値に対して行える比較を定める種類です。現在の Property 型は次の三つです。

| Property 型 | 利用者から見た値 |
| --- | --- |
| `text` | 文字列 |
| `number` | 精度を失わない数値 |
| `datetime` | タイムゾーンのずれを含めて一つに定まる時点 |

### Property 値

ある Entity の Property に設定された具体的な値です。値が存在しないことは null として表します。Property を作成時に指定する必要があるかどうかと、値が null になれるかどうかは別の性質です。

### 必須 Property

Entity を作成するときに、利用者が値を明示する必要がある Property です。必須であることは、null を禁止することを意味しません。

### default

任意 Property が Entity 作成時に指定されなかった場合に使う値です。既存 Entity の更新時には再適用しません。

### Link 型

二つの Entity 型の間にどのような関係を作れるかを定めたものです。Link 型は関係の意味と、from 側および to 側に置ける Entity 型を定義します。

### Link

二つの Entity の間に存在する、個別に識別可能な一つの関係です。Link は一つの Link 型に属し、from Entity と to Entity を結びます。

Link は二つの Entity を検索の都合で結合した結果ではなく、利用者が明示的に作成・削除するデータです。

### from / to

Link の向きを表す二つの端点です。from は関係の起点、to は関係の終点です。向きは Link 型が表す意味の一部であり、検索する方向によって入れ替わりません。

### ID

Entity または Link を、同じ型の他のものから区別するための不変な識別子です。表示名や Property 値が変わっても ID は変わりません。

## 操作を表す言葉

### 作成

新しい Entity または Link を登録する操作です。同じ ID と同じ内容を再度指定した場合は、同じ作成要求の再送として扱います。

### 取得

ID で一つの Entity または Link を指定して、その現在の内容を得る操作です。

### 更新

既存 Entity の、指定した Property 値だけを変更する操作です。ID、Entity 型、Link の端点は更新の対象に含みません。

### 削除

指定した Entity または Link を取り除く操作です。Entity に接続する Link が残っている場合、Entity は削除できません。

### list

一つの Entity 型または Link 型に属するデータを、0 件以上の並びとして取得する操作です。検索条件を指定しない list は、その型に属するすべてのデータを対象にします。

### page

list の結果を一度に返せる大きさに区切った一部分です。page を順に取得しても、各データの意味や検索条件は変わりません。

### cursor

同じ検索条件の次の page を取得するための印です。cursor の内部表現に利用者が意味を見いだしたり、内容を組み立てたりしません。

## 検索を表す言葉

### filter

list の対象から、どの Entity または Link を結果に含めるかを表す検索式です。filter を省略した場合は、絞り込みを行いません。

### 検索式

一つの述語、または複数の検索式を AND / OR で組み合わせたものです。AND と OR は相互にネストできます。

### 述語

一つの Entity または Link が満たすかどうかを判定できる、検索式の最小単位です。述語は検索対象、演算子、operand から成ります。

### 検索対象

述語が値を調べる対象です。Entity では ID または Property、Link では ID、from、to を検索対象にできます。

### 演算子

検索対象の値と operand をどのように照合するかを表す語です。

| 演算子 | 意味 |
| --- | --- |
| `eq` | operand と等しい、または operand の範囲内である |
| `ne` | operand と等しくなく、operand の範囲外である |
| `lt` | operand より前または小さい |
| `lte` | operand までを含めて前または小さい |
| `gt` | operand より後または大きい |
| `gte` | operand から後または大きい |
| `in` | operand の集合のいずれかに属する |
| `contains` | 指定した文字列を含む |
| `starts_with` | 指定した文字列で始まる |
| `ends_with` | 指定した文字列で終わる |
| `is_null` | Property 値が null である |
| `is_not_null` | Property 値が null ではない |

演算子ごとの厳密な範囲境界は[検索クエリの ADR](../adr/0014-define-list-api-search-queries.md)に従います。

### operand

述語で検索対象と比較する値です。Property 型と演算子に応じて、scalar、範囲値、またはそれらの集合を指定します。

### scalar

一つの `text`、`number`、`datetime` 値です。範囲を持たない単一の値を、範囲値と区別するときに使います。

### 範囲値

連続する `number` または `datetime` の範囲を一つの operand として表したものです。範囲の下端と上端、および各端点を範囲に含めるかを持ちます。月や日のような calendar 範囲も範囲値です。

### open / closed

範囲値の端点を、その範囲に含めるかどうかを表します。`open` は端点を含まず、`closed` は端点を含みます。

### calendar 範囲

特定の time zone における一か月または一日を表す `datetime` の範囲値です。期間の開始を含み、次の期間の開始を含みません。「2026 年 7 月」は末日の最終時刻を手入力するのではなく、7 月の開始から 8 月の開始までとして扱います。

### 集合所属

ある値が候補の集合のいずれかに一致することです。`in` 述語で表します。集合の各要素には scalar または範囲値を指定でき、要素間は OR として評価します。

### AND

子となる検索式をすべて満たすことを表す論理式です。

### OR

子となる検索式を一つ以上満たすことを表す論理式です。

### null

Property に値が存在しない状態です。空文字、数値のゼロ、未指定の検索条件とは区別します。検索では `is_null` または `is_not_null` だけで照合します。

## 実装上の言葉との境界

table、column、foreign key、JSON、HTTP、OpenAPI、Rust などは実装を説明する言葉であり、このユビキタス言語には含めません。実装文書では必要に応じて使用できますが、利用者に見える振る舞いを説明するときは、対応する Entity、Property、Link、検索式などの言葉を使います。
