# オントロジープラットフォームのユビキタス言語

この文書は、オントロジープラットフォームを利用してモデルを定義し、データを登録・検索する際に使う言葉と意味を揃えるためのものです。用語は利用者から見える概念で定義し、データベース、通信方式、生成コードなどの実装では定義しません。

## 用語一覧

| 日本語名 | 英語名 | 定義 |
| --- | --- | --- |
| オントロジー | Ontology | 対象世界にどのような種類のものがあり、それらがどのような情報と関係を持つかを表したモデル。 |
| オントロジー定義 | Ontology Definition | Entity 型、Property、Link 型を、プラットフォームが解釈できる形で記述したもの。実際の Entity や Link の集まりとは区別する。 |
| 内部表現 | Internal Representation | 検証済みのオントロジー定義を、生成処理が共通して利用できる形へ正規化した表現。 |
| スナップショット | Snapshot | ある時点の内部表現を、後から同じ意味で復元できるよう保存した記録。 |
| 正規化 | Normalization | 同じ意味を持つ表記の違いを取り除き、一つの表現に揃えること。 |
| エンティティ型 | Entity Type | 同じ種類の Entity が持つ意味と Property を定めたもの。 |
| エンティティ | Entity | 対象世界に存在する、個別に識別したい一つのもの。一つの Entity 型と不変の ID を持つ。 |
| プロパティ | Property | Entity が持つ一つの情報。Entity 型の中で名前、意味、Property 型、必須性を定義する。 |
| プロパティ型 | Property Type | Property が取り得る値と、値に対して行える比較を定める種類。 |
| プロパティ値 | Property Value | ある Entity の Property に設定された具体的な値または null。 |
| 必須プロパティ | Required Property | Entity の作成時に、利用者が値を明示する必要がある Property。 |
| デフォルト値 | Default Value | 任意 Property が Entity 作成時に指定されなかった場合に使う値。 |
| リンク型 | Link Type | 二つの Entity 型の間にどのような関係を作れるかを定めたもの。関係の意味と from/to の Entity 型を持つ。 |
| リンク | Link | 二つの Entity の間に存在する、個別に識別可能な一つの関係。一つの Link 型と不変の ID を持つ。 |
| 起点 | From | Link の向きにおける始点となる Entity。 |
| 終点 | To | Link の向きにおける終点となる Entity。 |
| 識別子 | ID | Entity または Link を、同じ型の他のものから区別する不変の識別子。 |
| 作成 | Create | 新しい Entity または Link を登録する操作。 |
| 取得 | Get | ID で一つの Entity または Link を指定し、現在の内容を得る操作。 |
| 更新 | Update | 既存 Entity の、指定した Property 値だけを変更する操作。 |
| 削除 | Delete | 指定した Entity または Link を取り除く操作。 |
| 一覧取得 | List | 一つの Entity 型または Link 型に属するデータを、0 件以上の並びとして取得する操作。 |
| ページ | Page | 一覧取得の結果を、一度に返せる大きさに区切った一部分。 |
| カーソル | Cursor | 同じ検索条件の次のページを取得するための、内部を解釈しない印。 |
| 絞り込み | Filter | 一覧取得の対象から、どの Entity または Link を結果に含めるかを表す検索式。 |
| 検索式 | Search Expression | 一つの述語、または複数の検索式を AND / OR で組み合わせたもの。 |
| 論理式 | Logical Expression | 複数の検索式を AND または OR で組み合わせた検索式。 |
| 述語 | Predicate | 一つの Entity または Link が条件を満たすかを判定する、検索式の最小単位。 |
| 検索対象 | Search Target | 述語が値を調べる対象。Entity では ID または Property、Link では ID、from、to を指定できる。 |
| 演算子 | Operator | 検索対象の値と比較値をどのように照合するかを表す語。 |
| 比較値 | Operand | 述語で検索対象と比較する単一値、範囲値、またはそれらの集合。 |
| 単一値 | Scalar | 一つの `text`、`number`、`datetime` 値。 |
| 範囲値 | Range | 連続する `number` または `datetime` の範囲を一つの比較値として表したもの。 |
| 開端 | Open Bound | 範囲値に含めない端点。 |
| 閉端 | Closed Bound | 範囲値に含める端点。 |
| 暦範囲 | Calendar Range | 特定のタイムゾーンにおける一か月または一日を表す `datetime` の範囲値。 |
| 集合所属 | Set Membership | ある値が候補の集合のいずれかに一致すること。`in` で表す。 |
| 論理積 | Logical AND | 子となる検索式をすべて満たすこと。 |
| 論理和 | Logical OR | 子となる検索式を一つ以上満たすこと。 |
| ヌル | Null | Property に値が存在しない状態。空文字、数値のゼロ、未指定の検索条件とは異なる。 |

## 内部表現とスナップショット

内部表現は、表記方法の違いを取り除いたオントロジー定義を、複数の生成処理が同じ意味で利用するためのものです。特定の実装言語における class や memory layout は、利用者から見た内部表現の意味には含めません。

スナップショットは内部表現を永続化したものです。同じ内部表現からは常に同じスナップショットが作られ、スナップショットからは同じ意味の内部表現を復元できます。保存形式の詳細は[正規化済みオントロジー snapshot の ADR](../adr/0015-define-normalized-ontology-snapshot-format.md)に従います。

## Entity 型、Entity、Property

Entity 型は同じ種類の対象が持つ情報を定義し、Entity はその種類に属する個別の対象を表します。Property は Entity 型の中で定義され、各 Entity が具体的な Property 値を持ちます。

Entity は保存先の行や通信上のデータではなく、利用者が識別して情報を持たせたい対象そのものです。同様に、Property は column や field ではなく、対象が持つ情報を意味します。

「Entity の型」「種類」も Entity 型と同じ意味では使わず、文書と会話では **Entity 型**に統一します。「属性」「field」「column」ではなくモデル上の概念を指す場合は **Property**を使います。

### Property 型

現在の Property 型は次の三つです。

| Property 型 | 利用者から見た値 |
| --- | --- |
| `text` | 文字列 |
| `number` | 精度を失わない数値 |
| `datetime` | タイムゾーンのずれを含めて一つに定まる時点 |

### 必須、null、デフォルト値

Property を作成時に指定する必要があるかどうかと、Property 値が null になれるかどうかは別の性質です。必須 Property も null を値として持てます。デフォルト値は作成時にだけ適用し、既存 Entity の更新時には再適用しません。

## Link 型、Link、向き

Link 型は作成可能な関係の意味と、その起点および終点に置ける Entity 型を定めます。Link は、その定義に従って二つの Entity を結ぶ個別の関係です。

Link は検索の都合で二つの Entity を一時的に組み合わせた結果ではなく、利用者が明示的に作成・削除するデータです。from/to の向きは Link 型が表す意味の一部であり、検索する方向によって入れ替わりません。

## 操作とライフサイクル

同じ ID と同じ内容を再度作成した場合は、同じ作成要求の再送として扱います。ID、Entity 型、Link 型、Link の起点と終点は更新できません。

Entity に接続する Link が残っている場合、その Entity は削除できません。先に Link を明示的に削除します。

## 一覧取得、ページ、カーソル

検索条件を指定しない一覧取得は、その Entity 型または Link 型に属するすべてのデータを対象にします。結果は ID 順にページへ分割します。

カーソルは同じ絞り込みの次のページを指します。利用者はカーソルの内部に意味を見いだしたり、値を組み立てたりしません。異なる絞り込みに同じカーソルを再利用することはできません。

## 検索式、論理式、述語

検索式は次のいずれかです。

- 一つの述語
- 一つ以上の検索式を持つ AND
- 一つ以上の検索式を持つ OR

AND と OR の子にも検索式を置けるため、論理式は相互にネストできます。述語は「検索対象」「演算子」「比較値」の組み合わせです。

### 演算子

| 演算子 | 意味 |
| --- | --- |
| `eq` | 比較値と等しい、または比較値の範囲内である |
| `ne` | 比較値と等しくなく、比較値の範囲外である |
| `lt` | 比較値より前または小さい |
| `lte` | 比較値までを含めて前または小さい |
| `gt` | 比較値より後または大きい |
| `gte` | 比較値から後または大きい |
| `in` | 比較値の集合のいずれかに属する |
| `contains` | 指定した文字列を含む |
| `starts_with` | 指定した文字列で始まる |
| `ends_with` | 指定した文字列で終わる |
| `is_null` | Property 値が null である |
| `is_not_null` | Property 値が null ではない |

演算子ごとの厳密な範囲境界は[検索クエリの ADR](../adr/0014-define-list-api-search-queries.md)に従います。

## 範囲値と集合所属

範囲値は下端と上端を持ち、それぞれを開端または閉端として指定します。単一値は両端が同じ閉区間として扱えます。`number` と `datetime` の比較では、単一値の代わりに範囲値を指定できます。

暦範囲は、指定したタイムゾーンにおける月または日を表します。期間の開始を含み、次の期間の開始を含まない半開区間です。「2026 年 7 月」は末日の最終時刻を手入力せず、7 月の開始から 8 月の開始までとして扱います。

`in` は範囲演算子ではなく集合所属です。集合の各要素には単一値または範囲値を指定でき、いずれか一つに一致すれば条件を満たします。

## 実装上の言葉との境界

table、column、foreign key、JSON、HTTP、OpenAPI、Rust などは実装を説明する言葉であり、このユビキタス言語には含めません。実装文書では必要に応じて使用できますが、利用者に見える振る舞いを説明するときは、対応する Entity、Property、Link、検索式などの言葉を使います。
