# ドキュメント規約

この文書は[共通規約](general.md)に加えて Markdown と説明 comment へ適用します。

## 記述

- 読者と目的を冒頭で明らかにし、結論または守るべき規則を背景より先に置きます。
- 一つの見出しでは一つの主題を扱い、見出し level を飛ばしません。
- domain の概念には[ユビキタス言語](../ubiquitous/platform.md)を使います。実装用語との境界を保ち、同じ概念に別名を増やしません。
- command、path、識別子、code 上の値は backtick で囲みます。link は相対 path を基本とし、参照先と同じ変更で有効性を確認します。
- 規則には「何をするか」を明記し、理由が判断に必要な場合だけ簡潔に添えます。曖昧な「適切に」「必要に応じて」だけで要件を表しません。

## Code 例

- 最小限でも実行または検証できる例にし、省略箇所がある場合は明示します。
- code fence には `rust`、`json`、`text` などの言語を指定します。
- 架空の credential や URL を使い、copy した利用者が実在環境へ誤接続しない値にします。
- API や生成形式を変更したときは、同じ PR で例を更新します。

## ADR

- 新しい ADR は [`docs/adr/template.md`](../adr/template.md)を複製し、連番を再利用しません。
- ADR の「決定」は単独で規範を把握できる内容にし、比較と理由は「検討」に置きます。
- 決定を置き換える場合は過去の ADR を改変せず、新しい ADR から変更対象を参照します。誤字や link 切れなど、判断を変えない修正は既存 ADR に行えます。
- 新しい domain 用語または意味の変更は、同じ PR でユビキタス言語へ反映します。
- 日付は `YYYY-MM-DD`、関連 ADR は番号の昇順で記載します。
