# アーキテクチャ概要

この文書は現時点のシステム像を共有するためのものであり、具体的な技術選定を確定するものではありません。確定した判断は [ADR](adr/README.md) を正とします。

## コンテキスト

```text
┌──────────────────┐       ┌──────────────────────────┐       ┌──────────────────┐
│ 入力アプリ／      │       │ データプラットフォーム     │       │ 活用アプリ         │
│ コネクター         │──────▶│                          │◀──────│                  │
└──────────────────┘  API  │ Ontology + Data + Policy │  API  └──────────────────┘
                           └──────────────────────────┘
```

周辺アプリはデータプラットフォームの内部ストレージへ直接アクセスせず、公開された API 契約を通じて更新・参照します。

## 概念モデル

- **Entity**: 不変の ID と型を持つ、利用者が個別に識別したい対象。
- **Property**: Entity だけが持つ属性。`text`、`number`、`datetime` の型と必須性を持つ。
- **Link**: 不変の ID と型を持ち、from Entity から to Entity を結ぶ有向辺。

オントロジーの定義（スキーマ）と、その定義に従う実データ（インスタンス）は区別します。具体的な表現は ADR で定めます。

利用者から見た各概念の意味は[ユビキタス言語](ubiquitous/platform.md)に従います。

## 境界と責務

### データプラットフォーム

- オントロジー定義とその変更を管理する。
- Entity、Property、Link の整合性を維持する。
- 更新・検索・参照の API 契約を提供する。
- 認証された主体に対して認可を適用する。

### 周辺アプリ

- 特定の入力元または利用目的に最適化した体験を提供する。
- 公開 API のみに依存し、プラットフォームの永続化方式に依存しない。
- 入力固有の形式を、共有されたドメインの意味へ対応付ける。
