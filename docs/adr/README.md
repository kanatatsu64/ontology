# Architecture Decision Records

ADR（Architecture Decision Record）は、重要な設計判断について、その背景、選択肢、結果を後から理解できるようにする記録です。

## 運用方法

1. 技術選定や変更不能性の高い判断を行う前に、[テンプレート](template.md)から ADR を作成します。
2. ファイル名は `NNNN-short-title.md` とし、番号を連番で付けます。番号は再利用しません。
3. 既存の判断を変更する場合、元の文書を書き換えず、新しい ADR から変更対象として参照します。
4. 「コンテキスト」と「決定」の間に「用語」を設け、その ADR で使う一般的でない用語を、文書単体で理解できるよう「用語」「定義」の表で簡潔に記述します。
5. 「決定」だけで決め事を把握できるよう、採用内容と適用規則を漏れなく、必要最小限に記述します。理由と比較過程は「検討」に記述します。
6. 「検討」の論点を `D-1`、`D-2`、…と採番し、各論点に判断基準、選択肢、採用を記述します。「採用」では採用した選択肢を明記し、各判断基準に沿って採用理由を記述します。
7. ADR で使う用語は[ユビキタス言語](../ubiquitous/platform.md)に準拠し、同じ概念を同じ言葉と意味で記述します。
8. ADR の作成または更新によって新しいユビキタス言語が生まれた場合は、同じ変更でユビキタス言語の用語一覧へ日本語名、英語名、定義を追記します。既存用語の意味を変更する場合も、ADR と用語一覧を同時に更新します。
9. 分量を抑えることを常に意識し、必要十分な記述にとどめます。1 つの ADR は 200 行を上限の目安とします。
